# 재무정보 저장 및 수집

증권 분석 상단의 **재무정보 수집** 메뉴에서 현재 시장의 전체 종목 업데이트를 시작한다. 연간·분기 손익계산서, 재무상태표, 현금흐름표를 모두 수집한다. 목록의 검색어나 화면 표시 개수 제한은 수집 대상에 영향을 주지 않는다. 사용자 지정 종목 목록 API가 설정되어 있으면 그 목록을 사용한다. 재무정보 자체의 공급자는 Yahoo Finance다.

- ES `stock_financials`에 종목·주기별 데이터, 시장별 설정 및 작업 체크포인트를 저장한다. 이전 응답에서만 존재하는 결산기간도 보존한다. 같은 기간의 유효한 새 값은 기존 값을 대체하므로 정정 전 수치의 버전 이력을 제공하는 구조는 아니다.
- 개별 조회와 AI 재무 문맥은 같은 저장소를 사용한다. 24시간 이내 확인한 데이터는 그대로 반환한다. 오래된 데이터는 먼저 반환하고 백그라운드 갱신한다. 화면은 갱신 상태를 조회해 새 데이터를 반영한다. 첫 조회는 공급자 응답을 기다린다.
- 수동 새로고침은 원본 공급자 조회를 요청하며 60초 재요청 제한을 적용한다. 자동 조회 실패는 15분 후 다시 시도할 수 있다. 실패 종목 재시도는 수동 제한을 적용한다. 진행 중인 동일 종목·주기의 요청은 공유한다.
- 빈 응답이 와도 이미 저장된 유효한 데이터를 지우지 않는다. 최초 빈 응답은 `empty`로 구분해 24시간 보관한다. 이는 공급자가 데이터를 반환하지 않았다는 뜻이며 실제 공시의 부재를 확정하지 않는다. 서로 다른 통화의 재무이력은 합치지 않는다.
- 전체 수집의 **매주 자동 업데이트**는 시장별로 설정하며 기본값은 꺼짐이다. 활성화하면 첫 실행 또는 지난 전체 수집 시작으로부터 7일 경과 시 실행한다. 최근 24시간 내 확인한 종목·주기는 재조회하지 않는다.
- 작업 진행률, 실패 수, 빈 응답 수를 표시한다. 실패 종목만 다시 수집할 수 있다. 일시정지는 자동 실행도 중단하며, 재개 시 처리 위치부터 이어간다.
- 백엔드가 종료되면 수집도 중단된다. 실행 중이던 작업은 다음 백엔드 시작 때 이어간다. 자동 실행 조건은 60초마다 확인한다. 수집 작업이 유지되므로 증권 분석 화면을 닫아도 백엔드가 실행 중이면 계속된다.

공급자 접근은 전체 수집과 개별 조회가 공통 잠금을 사용하고, 재무정보 묶음 조회 사이에 2초 간격을 둔다. 요청 제한 발생 시 120초 대기를 적용한다. 한 번의 묶음 조회에는 여러 Yahoo 요청이 포함되므로 전체 수집에는 상당한 시간이 걸릴 수 있다.

수집 스케줄러와 요청 공유는 데스크톱의 단일 백엔드 프로세스를 전제로 한다. 여러 백엔드를 같은 ES에 연결해 동시에 실행하려면 분산 작업 잠금이 추가로 필요하다. 주기 및 요청 제한 상수는 `financial_store.py`, 주간 실행 및 작업 처리는 `financial_collection.py`에서 관리한다.
